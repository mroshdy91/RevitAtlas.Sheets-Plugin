# Atlas Sheets

If Atlas tools cannot connect, follow the installed Atlas Core skill's agent-assisted installation reference. When setup is authorized, the agent runs Core's packaged helper; do not ask the user to configure tokens or install another Sheets engine. If Core is absent, install it through the selected marketplace first.

Follow the requested change intent. An ordinary edit does not require or automatically create a formal drawing revision, revision cloud, issue date or revision-table entry. Preserve existing issue history while making authorized edits. A formal revision includes only the requested change documentation and issue metadata; discover supported native revision/cloud actions before promising them, and report missing capability explicitly. Do not substitute static notes for native revision history. Tool `expected_revision` and model/presentation counters are concurrency controls, not drawing issue numbers.

For existing-sheet edits, start with Core `drawing_context` for the selected sheet; it returns placed views, titleblock instances and a bounded annotation page. `atlas_work.open` takes an RVT `path`; `create` takes an RTE `template_path`. New semantic keys and delivery basenames are lowercase letters/digits/underscores starting with a letter, at most 64 characters. Human-readable names remain separate. Adopt only objects you intend to edit.

Compile final requirements and bindings before saving, capturing and reviewing. `workflow_id` identifies the whole delivery; each new continuation is a different immutable request. Omit top-level `operation_id` on a new continuation. Reusing it retrieves only that original request's historical outcome, or rejects changed inputs; it does not refresh old checks. Checkpoint before reading `drawing_preservation`. It compares current saved elements with the signed pre-authoring starting copy and verifies original file bytes separately; initial Revit load/save normalization is outside its scope. Historical work without that snapshot remains incomplete. Model revision zero is not preservation proof.


For content counts, `sheet_view_count` means viewports only; `sheet_schedule_count` counts placed schedule segments excluding titleblock revision schedules; `sheet_content_count` sums both. Inspect before declaring an implementation-specific exact count. A view's `placements` shows existing sheet use. Sheet search includes sheet number, and sheet inspection groups titleblocks, views, schedules and notes. Adopt returned instances with a new semantic key before editing; generated `element_` keys are discovery identities.

Record the usable paper rectangle through layout `area`, or `arrange`, then run `check`. It measures every placed viewport including its label and every non-revision schedule segment. Keep the rectangle within the border and outside titleblock fields. Geometry checks cannot detect every text overlap or number bubble; keep generous border clearance and inspect enlarged border/title crops in the actual PDF. Declare the separate live sheet-title field with `title_region`, using inspected family field lines transformed into sheet coordinates. PDF verification checks the full current sheet name inside that field. A title extending into the client field must be corrected, even when no letters overlap. Never declare the whole titleblock as the title field. For an overflowing live title, inspect Core `drawing_titleblock`, adopt its instance and use `titleblock_variant` with the selected label ID, exact sample and expected type identity. It changes only the selected instance to a separate family with that label's text size changed. It does not infer the correct font size or replace live text. Review the result and verify the sheet title remains live.

This is a v2 interface. Previous source-action qualification does not establish native or installed qualification for this interface. Discover the loaded engine and action qualification first. A missing qualification grant is not permission to bypass the tools or edit engine records.

Use Core to open an owned standalone RVT copy and record the engineering drawing brief. Family is optional; existing titleblocks and annotation families can be used without family authoring. Do not modify linked documents or a live central/cloud model.

Inspect existing views, levels, view types, titleblocks and schedules through `atlas_inspect` actions `drawing_entities` and `drawing`. Filter discovery by `element_class` and `query`; dimension names alone do not identify a linear style. Reuse compatible project standards. If a suitable titleblock is absent, Core `drawing_standards` discovers installation-local content; `atlas_sheets_layout.load_standard` requires the selected family name and template hash. This reuses licensed local content without requiring Family or distributing Autodesk RFAs. Request the selected action contract through `atlas_catalog` before guessing unfamiliar inputs; contracts include syntax examples and current limitations.

`atlas_sheets_views` owns persistent plans/RCPs, sections, elevations, callouts and locked orthographic 3D views. Core navigation is temporary review, not permanent drawing creation. Use view updates to select hidden line, shaded, consistent colors or wireframe explicitly; shading is presentation, not proof of geometry. Section creation bounds use the explicit local frame; 2D crop updates use the current frame returned by Core drawing inspection. Revit can relocate that origin after creation. 3D bounds updates instead replace the section box with world-axis-aligned bounds; transform inspected corners into world coordinates first. Check `crop.update_bounds_frame`. Paper coordinates are millimetres; model coordinates have explicit units. Do not use template removal as an implicit workaround for controlled settings.

`atlas_sheets_layout` owns sheets, titleblock asset loading, viewport/schedule placement and arrangement. `atlas_sheets_sets` records sheet order. Adopt existing drawings explicitly by identity; do not recreate objects because the first reply was unclear. Recover its operation through Core. Existing schedules can be placed; ordinary schedule authoring belongs to the future Quantities surface. On the admitted MEP candidate, native panel schedules use the same placement, move, arrange and inspection tools and count as sheet schedules. MEP creates their electrical content; Sheets controls their paper placement. Read actual cells through MEP and review the exported sheet; cell text alone does not prove readability.

Use Annotations when dimensions, tags or notes must be authored. Measure native values and reference relationships independently of image judgment. Arrange with an explicit drawable area and gap. If content overflows, preserve required scale and text size and propose another sheet or an explicit scale amendment.

Save before capture: native save can change sheet metadata. Capture each sheet using Core `atlas_review.drawing_capture`, inspect the returned image at readable scale, then record the honest outcome through `atlas_review.drawing_record`. `atlas_validate.drawings` reports only drawing diagnostics and current sheet-image review. It does not prove engineering completeness. Bind numerical drawing expectations through Core requirements: `documentation` measures include actual dimension lengths/segments, view scales and sheet view counts, alongside sheet numbers/names and tag text.

Use `atlas_deliver.drawing_complete` after compiling requirements. It saves, checks evidence, exports and provides continuation requests. Choose explicit ISO paper/orientation when required; native sheet size may differ. `atlas_validate.drawing_pdf` independently parses and renders the exported PDF. Inspect each actual rendered page, then add honest outcome/observation through `atlas_review.drawing_pdf_record`. Resume `drawing_continue` with the same workflow identity for saved-RVT verification and a hashed RVT/PDF package. If interrupted, inspect `drawing_workflow`; do not restart authoring or rewrite records. A successful intermediate `drawing_export` is not a completed accepted delivery. Unsupported required behavior stays incomplete.

Linked RVTs are read-only inputs. Delivery retains exact dependency copies and their source paths/transforms. Original native reference paths remain unchanged; relocating the package may require repathing its copied links. Portable relative-path relinking is not a qualified capability.

Native sheet previews can retain cached model pixels. A no-model-candidates warning requires checking the intended view and crop; it is not automatically a failure for a 2D-only drawing. Actual PDF-page review remains compulsory, including blank or missing views.
